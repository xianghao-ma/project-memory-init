## 项目长期记忆与文档

开始工作时读取 [当前状态](docs/status.md)，按任务需要查阅 [关键决定](docs/decisions.md) 和 [结果索引](docs/results.md)，并核对原始证据。文档是有时间范围的记录，不能把旧状态当实时事实。

- `docs/` 顶层保留 `decisions.md`、`status.md`、`results.md` 三份长期记忆文件。专题分析、技术说明、调研、实验、测试和审计等详细报告Markdown统一写入 `docs/reports/`；结果索引只保留摘要和链接。
- `docs/figures/` 用于结果图片；每组的 `README.md` 保留在图片旁。已有 `docs/history/` 保持历史记忆归档用途。项目根README、AGENTS、skills及实验原始说明不因这一规则搬迁。
- 有重要决定、状态变化或新结果时自动更新相关文档；无实质变化不新增流水账。新决定替代旧决定时保留追溯，status保持当前有效。
- 决定记录原因、范围、日期和来源；状态注明检查时间与证据；结果注明目标、方法/配置、发现、验证及局限，并链接报告和原始产物。失败和负面结果也可记录。
- 区分用户决定、已核实事实、历史报告与假设；影响方向、科学解释或结果归属的疑义询问用户，不擅自补全。

## 结果图归档

图片存入 `docs/figures/YYYY-MM-DD_goal-name/`，日期采用北京时间（Asia/Shanghai）的产出日，英文简短目标名，正文中文。历史日期无法核实时用归档日，并注明原始日期未知；不只凭mtime推断创建时间。

同日同目标归同一目录；明显不同内容或目标另建同日期不同名目录。跨日产出创建对应日期目录并交叉链接。同名不同内容保留版本，不覆盖；相同内容避免重复复制。

每组必须有README.md，解释目标、数据/配置、各图含义、结论及限制、原图位置、生成脚本/命令（可核实时）与日期依据；在results.md加入入口。复制代表图保留原件，以SHA256核对一致性。FITS、大型采样链等留原处并链接，无可靠图时不制造图或空日期目录。

整理已有报告时保留当前工作区内容，更新迁移文档内部及外部引用，检查无新增断链；不从Git HEAD覆盖未提交修改。文档维护本身不触发科学计算、作业操作、Git提交或后台自动化。
